Skill-Gap Analysis

Team Skills Compared With Analytics Job Postings in NAICS 5415

Purpose

This page compares the skills requested in our analytics job postings with the current skills of our three team members. It answers two supporting questions from the Project Overview:

  • Where does the target user have skill gaps?
  • Which skills should the target user prioritize?

We use our own team as three realistic examples of the target user: early-career candidates moving into analytics roles within Computer Systems Design and Related Services (NAICS 5415).

NoteData Source

This analysis uses the corrected v2 extract described on the Data Preparation page: 1,790 analytics postings posted between September 2025 and September 2026. Unlike the original extract, v2 contains the full skill taxonomy, so core tools such as Python, SQL, Tableau, and Power BI are measured directly in the postings.

Each team member rated their current proficiency on the course’s five-point scale:

Score Level
1 Beginner

The skill list comes from the postings themselves: it covers the most requested tools and competencies that a person can realistically rate and learn. Very broad fields such as “Data Science” or “Computer Science” were left out because they describe a discipline rather than a skill.

3. Comparing Team Skills With Market Requirements

Job postings list skills but not the proficiency level employers expect. To compare the two, we set a target level for each skill using a transparent rule based on how often the skill is requested across all postings:

Demand in postings Target level
20% or more of postings 4 (Advanced)
10% to 19.9% 3 (Intermediate)
Under 10% 2 (Basic knowledge)

For each member and skill:

  • Gap = target level − current rating (0 if the member already meets the target)
  • Priority score = average team gap × share of postings

The priority score favors skills that are both widely requested and weak across the team. The Improvement Plan in Section 4 uses the same rule.

Show code 
def target_level(share):
    if share >= 20:
        return 4
    if share >= 10:
        return 3
    return 2


share = demand["Share of postings (%)"]
targets = share.map(target_level)

member_gaps = (targets - df_skills[targets.index]).clip(lower=0)  # members x skills

gap_table = pd.DataFrame(
    {
        "Demand (%)": share,
        "Target level": targets,
        "Team average": df_skills[targets.index].mean().round(2),
    }
)
gap_table = gap_table.join(member_gaps.T.add_suffix(" gap"))
gap_table["Average gap"] = member_gaps.mean().round(2)
gap_table["Priority score"] = (gap_table["Average gap"] * share / 100).round(2)
gap_table = gap_table.sort_values(["Priority score", "Demand (%)"], ascending=False)

# Saved as a handoff for the Improvement Plan and Career Strategy pages
gap_table.to_csv("data/processed/skill_gap_table.csv", index_label="Skill")

Gaps Measured Against Each Member’s Target Role

The targets above use demand across all postings. Because demand differs so much by role, we repeat the comparison using the postings for each member’s own target role, applying the same target rule to that role’s demand.

Show code 
TARGET_ROLES = {
    "Jenna": ["Business Intelligence", "Business Analyst"],
    "Mariam": ["Business Analyst"],
    "Juan": ["Data Scientist"],
}

rows = []
for member, roles in TARGET_ROLES.items():
    role_skills = panel.loc[panel["role_family"].isin(roles), "skills"]
    for skill, name in ratings["panel_skill_name"].items():
        role_share = role_skills.map(lambda s, name=name: name in s).mean() * 100
        target = target_level(role_share)
        current = int(ratings.loc[skill, member])
        if target > current:
            rows.append(
                {
                    "Member": member,
                    "Target role": " / ".join(roles),
                    "Skill": skill,
                    "Demand in role (%)": round(role_share, 1),
                    "Current": current,
                    "Target": target,
                    "Gap": target - current,
                }
            )

role_gaps = pd.DataFrame(rows)
role_gaps["Member"] = pd.Categorical(role_gaps["Member"], MEMBERS, ordered=True)
role_gaps = role_gaps.sort_values(["Member", "Demand in role (%)"], ascending=[True, False])
role_gaps.reset_index(drop=True)

This view sharpens each member’s priorities:

  • Jenna (Business Intelligence / Business Analyst): SQL is the most important gap by far, appearing in 45% of her target postings. Business requirements (Intermediate to Advanced) and Python follow. Her BI tool skills already meet the target for these roles.
  • Mariam (Business Analyst): SQL is the clear first priority, followed by business analysis and Excel, which each appear in about a third of Business Analyst postings. Python appears in only 14% of these postings, so it matters less for her target role than the market-wide view suggests.
  • Juan (Data Scientist): Python and machine learning are both requested in most Data Scientist postings, so machine learning is more urgent for him than the market-wide view suggests.

  1. Python and SQL are the team’s most important gap. They are the two most requested skills in the market, each in more than 60% of postings, and no one on the team is above Intermediate in either. Closing them matters for every target role on the team.
  2. Data pipelines are the largest gap relative to demand. They appear in about a fifth of all postings (and nearly half of Data Engineer postings), and the whole team is at Beginner or Basic level.
  3. The team’s business skills already meet the market. Across all postings, business requirements, business analysis, data analysis, Excel, and communication meet their targets for all three members. These are genuine strengths for the business analyst and BI roles that Jenna and Mariam are targeting.
  4. The team is complementary. Juan’s BI tool expertise, Jenna’s Excel, analysis, and communication skills, and Mariam’s business requirements skills cover different parts of the market, so peer teaching inside the team is a realistic first step before outside courses.
  5. Mariam has the most ground to cover, Juan the least. Mariam’s gaps span SQL, Python, and the BI tools, while Juan’s remaining gaps are concentrated in Python, SQL, pipelines, and machine learning.

Limitations

  • Assumed targets: Postings do not state a proficiency level. The target-level rule is a team assumption, stated above so readers can adjust it.
  • Self-ratings: Team ratings are self-assessed and not independently tested. Some ratings were carried over from an earlier skill list and mapped to the closest v2 skill, as recorded in team_skills_v2.csv.
  • Required versus preferred: Postings do not separate required skills from preferred ones, so demand shares may overstate how essential a skill is.
  • Small role groups: Business Intelligence has only 81 postings, so its role-specific shares are less precise than those for the larger role families.

4. Improvement Plan

Show code 
import json
import pandas as pd

_MEMBERS = ["Jenna", "Mariam", "Juan"]

_panel = pd.read_csv("data/processed/career_market_panel.csv")
_n = len(_panel)
_posting_skills = _panel["SKILLS_NAME"].fillna("[]").map(
    lambda s: set(json.loads(s)) if s.startswith("[") else set()
)

plan = pd.read_csv("data/processed/team_skills_v2.csv").set_index("skill")
plan["Demand (%)"] = plan["panel_skill_name"].map(
    lambda name: round(_posting_skills.map(lambda x: name in x).sum() / _n * 100, 1)
)


def _target_level(share):
    if share >= 20:
        return 4
    if share >= 10:
        return 3
    return 2


plan["Target"] = plan["Demand (%)"].map(_target_level)

_rows = []
for _member in _MEMBERS:
    for _skill, _row in plan.iterrows():
        _rating = _row[_member]
        if pd.isna(_rating):
            continue
        _gap = max(_row["Target"] - _rating, 0)
        if _gap > 0:
            _rows.append(
                {
                    "Member": _member,
                    "Skill": _skill,
                    "Current": int(_rating),
                    "Target": int(_row["Target"]),
                    "Gap": int(_gap),
                    "Demand (%)": _row["Demand (%)"],
                    "Priority": round(_gap * _row["Demand (%)"] / 100, 2),
                }
            )
plan_gaps = pd.DataFrame(_rows)

_pending = {m: [s for s in plan.index if pd.isna(plan.loc[s, m])] for m in _MEMBERS}
_pending = {m: s for m, s in _pending.items() if s}
if _pending:
    pending_note = (
        "Some ratings are still pending: "
        + "; ".join(f"{m} for {', '.join(s)}" for m, s in _pending.items())
        + ". Those skills are left out of the member's priorities until they are rated."
    )
else:
    pending_note = "All three members have rated every skill on the list."

This section turns the skill gaps into a plan. For each team member we identify the skills to work on first, suggest courses, certifications, and projects that close those gaps, and describe how the team can use its complementary strengths.

4.1 Setting Priorities

We use the same rule as Section 3 to set a target level for each skill, based on how often it is requested in the postings. A skill in 20 percent or more of postings gets a target of 4 (Advanced), one in 10 to 19.9 percent a target of 3 (Intermediate), and anything less a target of 2 (Basic knowledge). With the v2 data every skill on the list is measured directly in the postings, so no targets are assumed.

A member’s gap is the target minus their current rating, or zero if they already meet it. Their priority for a skill is that gap weighted by the skill’s share of postings, which favors skills that are both in demand and far from the member’s current level.

4.4 How the Team Can Help Each Other

Show code 
_strongest = plan[_MEMBERS].idxmax(axis=1)
_collab = plan_gaps.groupby("Skill").agg(
    **{
        "Members with a gap": ("Member", lambda s: ", ".join(s)),
        "Total gap": ("Gap", "sum"),
    }
)
_collab["Strongest on the team"] = [
    f"{_strongest[s]} ({int(plan.loc[s, _strongest[s]])})" for s in _collab.index
]
_collab.sort_values("Total gap", ascending=False)

Where one member is clearly ahead, they lead that topic. Where the strongest member still has a gap themselves, as with Python and SQL, the team studies together rather than relying on one person to teach. In practice:

  • A weekly study session of about an hour, working through the same Kaggle Learn or Zoomcamp module and comparing solutions.
  • Rotating who writes the code. For each remaining module of this project, the member with the largest gap writes the first version of the code, and the strongest member reviews it through a pull request. The work gets done and the practice counts double.
  • Pairing on the BI tools. The members strongest in Power BI and Tableau walk the others through rebuilding one Market Baseline chart in each tool.
  • Business framing from the business-side members. Members targeting business analyst roles lead on turning findings into requirements and recommendations for the Career Plan page.

4.6 Tracking Progress

At the end of each four-week phase, every member re-rates themselves in data/processed/team_skills_v2.csv. The tables in this section are calculated from that file, so the plan updates itself and shows which gaps have closed.
